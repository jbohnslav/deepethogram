# GPU integration testing via Modal

Set up on-demand GPU testing using Modal. Need to investigate Modal's image system, how to get our deps (PyTorch, CUDA, deepethogram) into a Modal image, and wire it into GitHub Actions for CI.

Key questions:
- Modal uses its own container image builder (modal.Image) — how do we get our full dep stack in there?
- Can we mount the repo or do we need to bake it into the image?
- What GPU types are available and cost per run?
- How to trigger from GitHub Actions?
- Test split: smoke test (1 training step, <2min) for PRs, full suite (20-30min) nightly

**Note (2026-03-29 16:47):** Researched Modal GPU CI for deepethogram. Recommendation: use one Modal app plus modal run from GitHub Actions, keep the current GPU suite in one container initially, and store tests/DATA/testing_deepethogram_archive (~1.2 GB, ~340 files) in a persistent Modal Volume mounted separately from the writable pytest workspace. Best first image strategy is to mirror docker/Dockerfile:test-headless with a Modal image built from nvidia/cuda:12.4.1-cudnn-runtime-ubuntu22.04 plus Python 3.11 rather than using from_dockerfile() directly, because the desired output is a multistage test-headless target and I did not find a documented Modal target selector. GPU inventory: 5 marked tests in tests/test_integration.py, 14 subprocess CLI jobs total, with hidden state dependencies between tests; PR smoke should be a new self-contained deg_f end-to-end path and nightly should keep the full suite. Public Modal compute pricing on 2026-03-29: T4 /bin/zsh.000164/s, A10 /bin/zsh.000306/s, A100-40GB /bin/zsh.000583/s, H100 /bin/zsh.001097/s; rough compute-only cost is about /bin/zsh.08-/bin/zsh.53 for an 8 min smoke run and /bin/zsh.25-.65 for a 25 min full run depending on GPU.
